# Run logs

One file per finished week (`week-01.md`, `week-02.md`, ...). Each run log has the same sections, so you can reproduce a week without reading its code:

1. **What was built**: files and the design decisions that matter.
2. **What I ran here**: commands and their actual results in the build environment.
3. **What you run on your machine**: numbered steps with expected output and time.
4. **Troubleshooting**: known failure modes and fixes.
5. **Checklist against the plan**: which plan items are done, and which wait on you.
6. **Open items**: decisions needed from you before the next week.

Results that matter for the research (profiles, gate numbers) live in `docs/data_profile/`, `docs/gates/` and the stamped artifacts, not in these logs.
